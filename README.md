# OvaBMҚ Companion

Электронные папки-дела по охране материнства и детства (Шурчинское районное медицинское объединение).

* **Сайт:** `docs/` — статичные файлы для GitHub Pages (без сборки).
* **База и вход:** `supabase/` — миграции Postgres (Supabase) и функция `tg-login`.
* **Показатели:** раздел «Показатели» на сайте — только числа за период по должностям; список показателей `docs/indicators.js` собирается скриптом `tools/gen_indicators.py` из файлов Baza_NN.
* **Беременные (миграция `0021`, главное):** с письменного согласия женщины регистр ведётся на сайте.
  - Доя — страница «Беременные»: постановка на учёт (Ф.И.О., дата рождения, телефон, махалля, адрес, ДПМ / ПДР по УЗИ, факторы и группа риска, дата согласия; бланк согласия печатается со страницы), список с фильтрами «визит сейчас / пропущен / патронаж / высокий риск / сигналы / без Telegram», карточка с планом визитов по приказу №180 (АД, вес, сданные анализы), роды и выписка, выгрузка в Excel.
  - Патронажная доя — страница «Патронаж»: обход по махаллям и улицам по приказу №210 (прил. 2): беременной на 12 и 32 неделе, родильнице и новорождённому — в 3 дня после выписки, на 15-й и 30-й день; отметка на месте; печать маршрута.
  - Руководители — «Сводка: беременные»: по учреждениям и махаллям — на учёте, высокий риск, пропуски визитов и патронажа, ранняя постановка, Telegram, сигналы; ссылки на списки, Excel.
  - **Группа риска — автоматически по протоколу №180 (миграция `0022`):** НКП «Антенатальный уход. Ведение беременных групп риска» (прил. 2 к приказу №180). Доя отмечает факторы анамнеза и текущей беременности, рост и вес — сайт сам считает ИМТ и риски: преэклампсия (1 высокий или ≥2 умеренных фактора), ГСД, ЗРП (1 большой или ≥3 малых), ВТЭО (баллы: 1–2 умеренный, ≥3 высокий), ПРК, преждевременные роды, резус-отрицательная кровь, анемия, юный возраст. Итог — «низкий/высокий риск» с причинами и рекомендациями протокола (аспирин, ПГТТ, УЗИ-контроль роста, тромбопрофилактика, анти-D и т. д.); пересчитывается при каждом сохранении (`private.risk180`, предпросмотр — `risk180_preview`).
  - **Сотрудники в Telegram (миграция `0024`):** сайт открывается прямо в боте (кнопка «Открыть OvaBMҚ» и «Меню» чата; вход по подписи Telegram — `tg-bot`, action=staff_app, без пароля). «Список на сегодня» — кому визит или патронаж сейчас и кто пропустил, с телефоном и махаллей; отметка «сделано» кнопкой (запись от имени сотрудника, дата — сегодня). Кнопки — и в утренней сводке.
  - **Графики по месяцам** на «Сводке: беременные»: постановка на учёт (и до 12 недель), высокий риск, роды, визиты и патронаж, сигналы из бота — за 12 месяцев.
  - **Беременной:** вопрос доя из «Моей страницы» (сотрудник отвечает ответом/Reply на сообщение бота — ответ приходит ей в Telegram; вопросы и ответы видны в карточке); напоминание о витаминах в выбранный час с кнопками «выпила»; после родов — вкладка «Малыш»: вес с графиком, кормление, прививки (видно доя в карточке).
  - **Направления, планирование семьи, отчёт за месяц (миграция `0025`):** направления в роддом / к специалисту / на анализы с отметкой «дошла» (просроченные видны в списке, фильтр «Направления»); метод послеродовой контрацепции (фильтр «ПС»); на «Сводке» — карта махаллей (плитки: зелёная / жёлтая / красная) и отчёт за месяц по учреждениям с выгрузкой в Excel; у ребёнка до 1 года — пол и график веса с коридором норм ВОЗ (у беременной — прибавка веса по нормам IOM).
  - **Дежурный роддома (миграция `0026`):** администратор отмечает сотрудника («Сотрудники» → «🏥 Дежурный роддома»); ему в Telegram приходят тревожные сигналы со всего района (кроме одного давления 140/90) и каждое утро в 08:25 — список женщин высокого риска, которым исполнилось 36 недель.
  - **Советы** (`docs/advice.js`, страница «Советы»): питание беременной и кормящей (что есть каждый день, что понемногу, что нельзя; анемия; тошнота, изжога, отёки) и памятка доя на одну страницу — обе печатаются; питание показано и в «Моей странице» беременной.
  - **Без интернета:** сайт кэшируется на телефоне (`docs/sw.js`), список беременных сохраняется при загрузке и открывается без сети (только чтение); при выходе из сайта удаляется.
  - **До и после** на «Сводке»: два месяца рядом — ранняя постановка, визиты, патронаж, направления, Telegram — для оценки пилота.
  - **Загрузка из Excel** («Беременные» → «Загрузить из Excel», шаблон на странице): доя загружает свой список одним файлом; сначала проверка каждой строки, потом постановка на учёт как обычно (дубли не создаются).
  - **Анализы (миграция `0027`):** гемоглобин, сахар натощак, белок в моче; сайт сам отмечает анемию (Hb < 110 г/л: лёгкая / средняя / тяжёлая), сахар ≥ 5,1 и ≥ 7,0 ммоль/л, белок «+» — пороги ВОЗ; фильтр «Анемия», столбец в отчёте за месяц.
  - **План родов:** где рожать, кто рядом, кто отвезёт и его телефон, документы, сумка; заполняет доя в карточке или сама беременная в «Моей странице»; с 36 недель без плана — отметка и фильтр «Без плана родов».
  - **Место при тревожном сигнале:** после сигнала бот предлагает кнопку «📍 Отправить, где я» (и в «Моей странице»); доя, руководителю и дежурному роддома приходит точка на карте, в карточке — ссылка на Google и Яндекс.
  - **Областной сервер:** порядок установки — `DEPLOY_VILOYAT.md`; ночная зашифрованная копия базы — `supabase/ops/backup.sh`.
  - Дневник давления: беременная пишет давление в бот («120/80») или в «Моей странице»; 140/90 и выше — сообщение доя, 160/110 — «звоните 103». Дневник виден в карточке.
  - Беременная — бот @OvaBMQbot: доя даёт одноразовый QR/ссылку → язык → согласие; «Моя страница» (мини-приложение `docs/mother.html`, подпись Telegram проверяется в `tg-bot`): срок, ПДР, следующий визит и анализы, патронаж, звонок доя; меню бота: «Мой визит и анализы», «Давление», «Питание, витамины», «Образ жизни», «Когда к врачу», «Роды», «После родов», «Моя доя» (справка — по разделу «Информация для пациентки» протокола №180); мини-приложение «Моя страница» (миграция `0023`) устроено как приложение с нижним меню: «Главное» — кольцо срока, триместр, сколько дней до родов, размер малыша по неделям, полоса визитов по №180, витамины на сегодня, кнопка «Мне плохо»; «Графики» — давление (с границей 140/90), прибавка веса с полосой нормы IOM (2009) по ИМТ, витамины за 14 дней; «Дневник» — давление, вес, витамины (доя видит их в карточке); «Советы»; «Ещё» — счётчик схваток (с 24 нед: ≥4–5 в час до срока — сигнал доя), счётчик шевелений «10 за 2 часа» (с 28 нед), сумка в роддом; советы по сроку раз в несколько недель; тревожные признаки (список протокола №180) → сразу «звоните 103» и сообщение доя/патронажу/руководителю её учреждения; напоминания о визитах (`supabase/ops/schedule_mothers.sql`), утренняя сводка доя; /stop — отключиться.
  - Видят: клинические должности своего учреждения (доя, патронажная доя, патронажная медсестра, акушер-гинеколог, семейный врач), руководитель учреждения, главный акушер-гинеколог и руководство района. В журнал Ф.И.О. не пишутся.
* **Офлайн-программа (отложена, в меню скрыта):** `offline/` — один HTML-файл без интернета (импорт Excel от специалистов, напоминания, поиск по данным пациентов, шифрование; вкладка «Визиты» — пациенты по № карты, беременные по стандарту приказа №180 (ДПМ → срок, окна визитов, анализы, пропущенные визиты; всё на устройстве), махалля/улица/диагноз, фото осмотра с камеры телефона, напоминания, отправка для будущего сервера; всё только на устройстве). Сборка: `python3 offline/build.py`, проверка: `python3 offline/tests/test_offline.py` и `python3 offline/tests/test_cases.py`.
  Для телефонов — устанавливаемое приложение: https://richerdsuper-pixel.github.io/ovabmk-companion/app/ (Chrome → «Установить приложение»; работает без интернета).
  Должность в программе выбрать нельзя: её назначает администратор на сайте («Сотрудники» → «Офлайн-программа»), а сотрудник получает ключ активации на странице «Офлайн-программа» (или администратор выдаёт его кнопкой «Ключ для сотрудника»). Ключ подписан сервером (ECDSA P-256, функция `offline-key`, закрытый ключ — в закрытой таблице `private.offline_sign_key`, открытый — `offline/sign_pub.json`), срок активации 30 дней; после активации программа работает без срока. В ключ входит открытый ключ шифрования администратора (его администратор вставляет на сайте из своей программы): файлы доя шифруются им (ECDH P-256 + AES-GCM) и открываются только у администратора — без паролей.

* **Отпуск и замещение** (страница «Отпуск и замещение», миграция `0015`): сотрудник сам указывает свою ставку (0,25–1,5), администратор подтверждает. Заявка на отпуск — с выбором замещающего коллеги того же учреждения; замещающий даёт согласие (ТК РУз, ст. 116), нагрузка замещения 0,3 ставки, вместе со ставкой и другими замещениями — не больше 1,5 (лимиты — `private.max_rate()` / `private.sub_load()`). Рассматривает руководитель учреждения (область видимости «учреждение» в «Сотрудниках»). Если он не ответил 2 рабочих дня, администратору приходит уведомление в Telegram (pg_cron `leave-escalate-0900`, функция `leave-escalate`, `supabase/ops/schedule_leaves.sql`), и администратор может «Потребовать рассмотрения» (функция `leave-notify`). После одобрения замещающий получает в новом ключе офлайн-программы вторую должность до конца отпуска; пациентки передаются напрямую — файлом, зашифрованным ключом устройства замещающего (он сохраняется на сайте из «Настроек» программы), и возвращаются после отпуска.
  При первом запуске выбирается должность: **доя кабинета** (беременные по приказу №180 — ДПМ, срок, анализы, группа риска, возрастная группа; списки скрининга по приказам №210 и 47-Т: осмотр 15–49 лет раз в год, шейка матки 35–55 раз в 3 года, молочная железа 45–65 раз в 2 года), **патронажная доя** (патронаж по приказу №210, приложение 2: беременная 12 и 32 нед., родильница и новорождённый — 3 раза) или **администратор**. Вкладка «Сегодня» — обход по махаллям и улицам; «Отчёт» — числа за месяц и файл с числами для сайта (без людей), кнопка «Отправить администратору» (зашифрованный файл, только изменения; Ф.И.О./телефон/адрес — только если изменились; код отправки задаётся один раз и больше не спрашивается, на телефоне сразу открывается «Поделиться»), календарь на все будущие визиты. Языки: русский, узбекский (кириллица и латиница); тексты приказа №180 по-узбекски — `offline/anc.json`.
* **Подпапки:** в каждой из 20 папок — подпапки (разделы), всего 140; номера совпадают с бумажными разделителями. Названия — русский и узбекский латиницей. Для каждой подпапки задано: где хранится (**сайт** — файл; **только цифры** — список с ФИО остаётся на бумаге/в офлайн-программе, на сайт — число и отметка; **только бумага** — на сайт только отметка), кто сдаёт (коды должностей из `docs/positions.js`), периодичность и срок (ежемесячно до 5 числа, ежеквартально до 10 числа, ежегодно до 15 января, однократно, по поступлению, по случаю) и нужен ли бумажный оригинал. Исходник — `tools/subfolders_data.py` (утверждён заместителем 25.10.2026), миграция собирается `python3 tools/gen_subfolders.py > supabase/migrations/0018_seed_subfolders.sql`; дальше настройки меняет администратор на сайте. Страница «Сроки сдачи»: у каждого — свои подпапки по должности (просрочено / срок скоро / сдано), у руководителей — контроль по району и кнопка «Напомнить» (Telegram через `tg-notify`, только несдавшим). Руководитель отмечает «бумажный оригинал получен». Сроки считаются с 1 ноября 2026 г. **Автонапоминания** (миграция `0019`, функция `sub-remind`, pg_cron `sub-remind-daily` в 09:07 и `sub-remind-weekly` по понедельникам в 09:12, `supabase/ops/schedule_subfolders.sql`): за 2 дня до срока и после срока (один раз), если не сдано; одно сообщение на человека со списком подпапок; в утверждённом отпуске — не беспокоим; по понедельникам администраторам — сводка несданного. Кто должен сдавать — по названию должности в профиле (`private.position_names`, при изменении `docs/positions.js` обновить и её) и открытым папкам. На странице подпапки руководитель видит «бот напомнил».
* **Проверки:** `tests/` — тесты прав доступа (локальный Postgres), подписи Telegram и интерфейса.

## Как устроен доступ

| Роль | Что может |
|---|---|
| Администратор | всё, кроме папки №15; сотрудники, роли, приглашения, журнал, удаление документов |
| Заместитель, Главный врач | читать и добавлять документы во всех папках, кроме №15 |
| Сотрудник | читать и добавлять документы только в назначенных папках; вносить и править свои показатели |

* **Регистрация и вход** (миграция `0020`, функция `tg-bot`): на сайте сначала анкета — ФИО полностью, телефон (+998), место работы, одна или несколько должностей со ставками (шаг 0,25, всего не больше 1,5). Кнопка «Подтвердить в Telegram» открывает бота @OvaBMQbot (`t.me/OvaBMQbot?start=<код>`), человек нажимает «Старт» — заявка подана; окна входа Telegram и повторного подтверждения нет. Администратор видит в «Заявках» телефон, должности и ставки; папки уже отмечены по всем должностям (объединение, `private.position_names`), после «Одобрить» бот присылает «Доступ открыт» с кнопкой «Войти» (`?login=<код>`), и сайт входит сам. Сотрудник, который уже зарегистрирован, нажимает «Войти через Telegram» → «Старт». В браузере хранится только секрет билета (`localStorage`), в базе — хеши кодов (`private.login_tickets`). Webhook бота: `supabase/ops/setup_bot.sql`. Запасной вход через окно Telegram: адрес с `?widget=1`.
* Вход — только через Telegram: по одноразовому приглашению или по заявке. Общая ссылка на сайт: человек входит через Telegram, пишет ФИО и выбирает должность; администратор в разделе «Заявки» видит папки, отмеченные по должности автоматически (`docs/positions.js`), при необходимости меняет их и одобряет или отклоняет. До одобрения учётная запись не создаётся и доступа к данным нет.
* Роли меняются только функциями базы, которые сами проверяют роль администратора; из браузера записать роль нельзя.
* Папка №15 «Материнская смертность» закрыта для всех, включая администратора (проверка в базе и в хранилище файлов).
* Документы с данными пациентов (ФИО, ПИНФЛ, диагнозы) загружать нельзя: при загрузке это нужно подтвердить, а база не примет документ без подтверждения.
* Показатели: сотрудник видит и правит только свои отчёты, руководители видят все. В таблице только числа (база отклоняет текст, чужие ключи и огромные значения), поэтому внести туда данные пациентов нельзя.
* Все действия пишутся в журнал (виден администратору).

## Настройка (один раз)

1. **Бот:** @BotFather → `/newbot`; затем `/setdomain` → `richerdsuper-pixel.github.io`.
2. **Токен бота:** Supabase → проект → Edge Functions → Secrets → `TELEGRAM_BOT_TOKEN`. Токен никому не пересылайте.
3. **Регистрация:** Supabase → Authentication → Sign In / Providers → выключить «Allow new users to sign up» (вход по приглашениям работает и без неё).
4. **GitHub Pages:** Settings → Pages → Deploy from a branch → `main` / `docs`.
5. **Первый администратор:** Supabase → SQL Editor:
   ```sql
   select private.make_invite(null, 'admin', 'ФИО', 'Должность', '{}', 24);
   ```
   Запрос вернёт код. Откройте `https://richerdsuper-pixel.github.io/ovabmk-companion/?invite=КОД` и войдите через Telegram. Ссылка одноразовая и действует 24 часа. Дальше сотрудников приглашаете из раздела «Приглашения».
