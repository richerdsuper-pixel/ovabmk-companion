# OvaBMҚ на сервере вилоята — порядок установки

Сейчас сайт работает на облачном Supabase (демо). Если хокимият одобрит, систему переносят на свой сервер в Узбекистане.
Код и база те же — меняются только адреса и ключи. Ниже — что нужно и в каком порядке.

## 1. Что нужно

| Что | Минимум | Зачем |
|---|---|---|
| Сервер (Linux, Ubuntu 22.04/24.04) | 4 ядра, 8 ГБ памяти, 200 ГБ SSD | база, сайт, бот |
| Доменное имя и сертификат HTTPS | например `ovabmk.surxondaryo.uz` | без HTTPS Telegram не откроет «Мою страницу» |
| Выход в интернет | постоянный, белый IP или прокси | Telegram присылает сообщения на сервер |
| Второе место для копий | другой сервер или диск в другом здании | восстановление при поломке |
| Ответственный | 1 администратор (IT) | обновления, копии, доступ |

Персональные и медицинские данные хранятся на сервере в Узбекистане. Перед запуском — согласовать с юристом
порядок обработки персональных данных (Закон «О персональных данных») и форму письменного согласия (есть на сайте: `#/consent`).

## 2. Установка (делает IT)

1. Установить Docker и Docker Compose.
2. Развернуть Supabase (self-hosted): `git clone --depth 1 https://github.com/supabase/supabase`, папка `docker/`,
   заполнить `.env` — свои пароли и ключи (`POSTGRES_PASSWORD`, `JWT_SECRET`, `ANON_KEY`, `SERVICE_ROLE_KEY`), адрес сайта.
3. Применить миграции по порядку: `supabase/migrations/0001_…sql` … последняя (команда `psql -f` для каждого файла).
4. Функции (`supabase/functions/*`) положить в папку функций контейнера `edge-runtime`; задать секреты:
   `TELEGRAM_BOT_TOKEN`, `SITE_URL`, `ALLOWED_ORIGINS` (ключи хранятся только в секретах сервера, в репозиторий не кладутся).
5. Сайт (`docs/`) раздать через nginx или caddy с HTTPS; в `docs/config.js` вписать новый адрес Supabase и `anon`-ключ.
6. Telegram: у @BotFather можно оставить того же бота. Выполнить `supabase/ops/setup_bot.sql` (или вызвать `tg-bot` с `{"action":"setup"}` и заголовком `x-cron-secret`) — бот переключится на новый сервер.
7. Планировщик: выполнить `supabase/ops/schedule_mothers.sql` и остальные файлы `supabase/ops/schedule*.sql`, заменив в них адрес на новый.
8. Первый вход: администратор входит через Telegram, остальные сотрудники — по анкете (как сейчас).
9. Демо-данные **не** загружать (`demo_seed.sql` только для показа).

## 3. Резервные копии

- Каждую ночь — `supabase/ops/backup.sh` (по cron в 02:30): полная копия базы, зашифрованная, хранится 14 дней,
  и копируется во второе место.
- Раз в месяц — проверка восстановления на отдельной машине: `pg_restore` последней копии и вход на сайт.
- Файлы (вложения в папках-делах) — копировать папку хранилища Supabase тем же скриптом.

## 4. Безопасность

- Вход на сервер — только по SSH-ключам, без пароля; порт базы наружу не открывать.
- Обновления Ubuntu — ежемесячно; обновления Supabase — после проверки на копии.
- Все права доступа проверяет база (RLS): каждый видит только своё учреждение; руководитель района — всё.
- Журнал действий (`audit_log`) хранит входы, привязку Telegram, отключение беременных от бота.
- Ключи бота и подписи — только в секретах сервера.

## 5. Проверка после установки

```
sh tests/reset_local.sh && python3 tests/rls_test.py   # права доступа на копии базы
python3 tests/ui_test.py                               # интерфейс
```
Затем вручную: вход сотрудника через Telegram, постановка тестовой беременной, приглашение в бот, сигнал «тревожный признак», удаление тестовой записи.
